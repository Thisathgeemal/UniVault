# Evidence guide: issuer portal login and layout (S2, Sprint 1 carry-over)

What to open and click for each screenshot of the issuer portal login and protected layout
(Decisions 015 and 016, [docs/frontend/issuer-portal.md](../../frontend/issuer-portal.md)).
Save each one in this folder under the file name given.

## Before you start

1. Two PowerShell terminals:
   - `cd backend; npm run db:seed; npm run dev`: API on http://localhost:4000.
   - `cd issuer-portal; npm run dev`: portal on http://localhost:5173.
2. Seed logins (synthetic, **development only**). The password is the development seed
   password that `npm run db:seed` prints:
   - **Admin:** `admin@serendib-trading.example`
   - **Officer:** `officer@serendib-trading.example`
   - **For the lockout shot only:** `officer@lanka-agro-tools.example`, so the main accounts
     are not locked.
3. Use Chrome or Edge, a normal window of about 1280 × 800, zoom 100%. Open DevTools with F12
   where a step says so.
4. **Never show the password or a token value in a screenshot.** Type the password into the
   field (it shows dots). In DevTools, crop or blur the token value: the key name is enough.

**Dashboard (25 Nov):** the dashboard replaced the welcome placeholder, so shots 13 and 18 now

**Afterwards:** the locked account (`officer@lanka-agro-tools.example`) unlocks by itself after
15 minutes. `npm run db:reset` in `backend/` also clears it, but it deletes ALL development
data (holders, credentials, published issuer keys), so you would have to run `npm run
keys:init` again. Prefer waiting.
